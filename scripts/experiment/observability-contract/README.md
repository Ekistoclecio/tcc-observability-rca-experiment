# Common Observability Contract v1

The fault-independent contract is implemented by `scripts/experiment/dataset/contract.py` and described by the three JSON documents alongside this file. RAW Prometheus, Loki, and Jaeger responses remain unchanged; the contract applies only to normalized per-run RCA datasets and the model-visible Common RCA View. RAW family/series/sample counts are audit-only and are not a parity blocker by themselves.

## Metric contract

The common metric concepts are `request_count`, `request_duration`, and `cpu_utilization`. Counts and duration histograms use window deltas, not the cumulative final counter value. A counter reset is detected between adjacent samples and its post-reset increment is accumulated. A series is `missing_baseline` if it has fewer than two samples or its first sample occurs after the requested window start; this avoids interpreting a newly appearing cumulative series as a zero baseline. Histogram buckets are excluded. Duration is represented by count delta, sum delta, and average in seconds. CPU is derived from the same cAdvisor `container_cpu_usage_seconds_total` source, scraped independently by Prometheus A and the OTel Collector B, then represented as first/min/max/average/last CPU cores in the window. CPU cores are usage, not a percentage of a container limit.

Request dimensions are service, fixed logical operation, client/server/datastore kind, target when relevant, and success/error outcome. SDK, exporter, process, runtime, host and arbitrary resource labels are not copied into the common metric view. Native metric family names may remain in the normalized dataset for audit but are removed from the Canonical RCA Request; the model sees `concept`, not instrument-specific family names.

## Log contract

Both scenarios retain canonical SUT application events with timestamp, service, canonical severity, message and useful application attributes. An event without safely classifiable severity is excluded from the Common RCA View, as are stack frames and known runtime/health/lifecycle noise; these records remain untouched in RAW. Error aliases such as `error` and `exception_message` map to `error.message`; exception type and stack location are excluded unless an equivalent common fact is established. B's native `trace_id` and `span_id` remain present; A receives no synthetic correlation. SDK/resource and process/runtime identity fields are omitted from the compact RCA view.

### Canonical Log Inclusion Policy

`canonical_log_classification(log)` is the single fault-independent classifier used by normalization, parity comparison, audit sampling, and classification reports. `APPLICATION_ERROR`, `APPLICATION_WARNING`, and recognized `APPLICATION_DIAGNOSTIC` events are model-visible. Explicit health checks, known runtime/SDK/platform noise, and process/datastore lifecycle output are excluded as `HEALTH_CHECK`, `RUNTIME_NOISE`, and `LIFECYCLE_NOISE`. A narrowly recognized successful `Transaction processed` event is classified as `REDUNDANT_SUCCESS_EVENT` because the same successful operation is already represented by request count/duration and canonical trace outcome; this does not remove success logs generally. `UNKNOWN` events are not model-visible by default. Every excluded record remains in RAW. The classifier does not inspect scenario, fault metadata, or Ground Truth. B correlation IDs are not part of canonical factual event identity.

## Trace contract

The common logical span envelope uses service, operation, kind (`server`, `client`, `datastore`), target, start, duration, canonical `SUCCESS`/`ERROR`/`UNKNOWN` status, parent relationship and native trace/span IDs. Outcome normalization is shared by the Dataset Builder, parity validator and audit sampler, and reads conventional `attributes.result`, OTel status, gRPC response codes, HTTP response codes and explicit error flags. Redundant native attributes, SDK/resource metadata, source-code location and span event payloads do not enter the model-visible request after their canonical fields are extracted. The static Online Boutique operation catalog is shared by A/B. Health, scrape and observability exporter spans are excluded as non-application noise. Traces are deduplicated by trace ID and spans by span ID.

## Parity and limitations

Selection and normalization are independent of the fault class and Ground Truth location. The Builder does not equalize counts, sample, truncate, choose errors, or consult the other scenario's output. Differences in trace IDs, parent context, log correlation and representation are intentional. Parity is evaluated on the Common RCA View, not by requiring equality of complete RAW metric families, series, samples, traces or bytes. The before/after audit reports compare fixed logical concepts; a missing concept is a parity failure, not a reason to filter its counterpart.

The earlier F4 metric investigation established that a shared Prometheus range-query step of `1s` avoids a 5s evaluation-grid miss, while the 5s Prometheus scrapes and OTel metric reader/Collector path can still produce documented cutoff lag. Missing counter baselines remain `null`/`missing_baseline`; no zero is invented and no metrics are derived from traces. The new canonical span/log and model-visible filtering changes require a fresh F4/F5 smoke before the full F1–F5 validation. RAW data remains unchanged and is not parity-gated by family/series/sample counts.
